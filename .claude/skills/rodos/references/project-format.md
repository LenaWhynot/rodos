# Файл семейного проекта

Храни рабочий `family.json` в отдельной папке семьи. Используй постоянные ID, чтобы исправление даты или фамилии обновляло ту же карточку. Рабочие заметки, оригиналы и журнал поиска могут лежать рядом. Версия формата для атласа — `schema_version: 1`.

| Поле верхнего уровня | Содержимое |
| --- | --- |
| `title` | Название атласа |
| `root_id` | ID человека, от которого показываем дерево |
| `is_demo` | Необязательный флаг `true` для вымышленного примера |
| `people` | Карточки людей |
| `relationships` | Родительские связи и версии |
| `sources` | Семейные и документальные источники |

Начать можно с одной карточки и пустых списков связей и источников.

```json
{
  "schema_version": 1,
  "title": "Моя семья",
  "root_id": "p-001",
  "people": [
    {"id": "p-001", "name": "Анна", "questions": ["Где она родилась?"]}
  ],
  "relationships": [],
  "sources": []
}
```

ID содержат от 1 до 64 букв латиницы, цифр, дефисов и подчёркиваний. Первый символ — буква или цифра. ID уникальны в своём списке.

- **Карточка.** Обязательны `id` и `name`. Дополнительно можно указать `life_years` и `summary` строками, `questions` списком строк, `portrait` как встроенный data URI для PNG, JPEG или WebP. Список `facts` содержит объекты с полями `title`, `text`, `status` и `source_ids`. Даты, места, варианты имени и биографические сведения указывай отдельными фактами с источниками. Пропущенные поля просто опускай. При расхождениях сохраняй каждое чтение со своим источником.
- **Связь.** Запись `{"id":"r-001","kind":"parent_of","parent_id":"p-002","child_id":"p-001","role":"mother","status":"family","source_ids":[]}` связывает две существующие карточки. Необязательная роль `father` или `mother` у родителя точки отсчёта определяет сторону дерева. У других родственников стороны выводятся из родительских связей. Родители расположены выше своих детей. Если все связи допускают шаг в одно поколение, сиблинги остаются в одном ряду даже при разной глубине потомков. Родственные сведения других типов можно сохранить как факты карточки.
- **Источник.** Обязательны `id` и `title`. Дополнительно `kind` указывает тип, `locator` — шифр и лист или идентификатор семейного материала, `excerpt` — проверенную выписку, `url` — явную ссылку HTTPS. Копия и индекс той же записи относятся к одной цепочке. В атлас идут только источники, на которые ссылаются факты или связи.
- **Статус.** `family` — сообщение семьи, `documented` — прочитанный документ с конкретным `source_ids`, `hypothesis` — версия, `disputed` — существенное расхождение. Две первые категории видны на дереве разными линиями. Версии и расхождения открываются внутри карточки. Совпадение имени само по себе хранится отдельной карточкой до проверки.

Статусы здесь нужны для отображения. Более подробную оценку доказательств, варианты поиска и охват храни в рабочем журнале или в дополнительных полях проекта. Атлас показывает только описанные поля. Сохраняй исходник и дополняй его проверенными дельтами.

## Сборка

```sh
python3 /путь/к/rodos/scripts/build-atlas.py /путь/к/family.json /путь/к/atlas.html
```

Открой созданный HTML в браузере. Он работает локально, включая портреты и выписки. Внешняя ссылка открывается по действию человека. Страница содержит показанные семейные сведения, поэтому обращайся с ней как с исходным семейным файлом.
